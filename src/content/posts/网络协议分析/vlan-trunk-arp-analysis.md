| 二、实验原理与内容 实验原理： ICMP协议 ICMP用于在IP主机和路由器之间传递控制消息，如网络连通性、主机可达性等。 路由重定向 路由器通过ICMP消息通知源主机将数据转发路径改为更优路径。 RIP V2协议 距离矢量路由协议，以跳数为度量，最大跳数为16，使用组播地址224.0.0.9。 OSPF协议 链路状态路由协议，支持分层区域，使用组播地址224.0.0.5，包含五种报文类型。 实验内容： 搭建网络拓扑并配置IP地址； 配置RIP和OSPF协议； 抓包分析ICMP路由重定向； 抓包分析RIP和OSPF协议报文。 |

（1）RIP协议周期性地交换路由的目的IP地址是多少？ RIP协议周期性地交换路由信息所使用的目的IP地址是 224.0.0.9。  （2）在以上拓扑结构中，周期性地交换路由，能否抓到R3给R1发送的RIP报文，并解释原因； 不能。原因如下： R1 和 R3 是直连的（通过 13.0.0.0/24 网络）。 R1 和 R3 之间没有运行RIP协议的路由器。 RIP v2 的一个重要改进是水平分割 (Split Horizon)。水平分割的规则是：从一个接口学习到的路由信息，不会再从同一个接口发送出去。 其工作原理如下： R1 从它的 F0/0 接口（连接 12.0.0.0/24 网络）收到 R2 发来的关于 24.0.0.0/24 网络的路由。 当 R1 要发送RIP更新时，它不会将 24.0.0.0/24 这条路由再从 F0/0 口发回给 R2，同样，它也不会将这条路由从 F0/1 口发送给 R3。 同理，R3 直连的网络只有 13.0.0.0/24。R1 本身就直连这个网络，所以 R3 没有需要告诉 R1 的、R1 还不知道的新路由。 由于水平分割和RIP的触发更新机制，在稳定状态下，两个直连的路由器之间，如果它们之间没有其他路由器需要学习路由，它们就不会向对方发送包含有效路由的RIP更新。它们可能仍然会发送更新，但更新报文中不会包含路由条目（或者只有默认路由，如果配置了的话）。 因此，在 R1 和 R3 之间的链路上抓包，你很可能只能看到空的RIP响应报文，或者完全抓不到周期性的更新报文，因为两者都没有需要告知对方的新路由信息。  （3）R2发送给R1的RIP报文中包含哪些路由信息？R1发送给R3的RIP报文包含哪些信息？ R2 发送给 R1 的 RIP 报文包含的路由信息： 24.0.0.0/24：这是 R2 的 F0/0 接口直连的网络。 （可能包含）12.0.0.0/24：这是 R2 的 F0/1 接口直连的网络。但由于水平分割，R2 通常不会将它从 R1 那里学来的 12.0.0.0/24 再发回给 R1。然而，对于直连网络，有些实现仍然会通告。更可能的情况是，由于 12.0.0.0/24 是 R1 和 R2 的共享网络，R2 会通告它，但跳数为1。  R1 发送给 R3 的 RIP 报文包含的路由信息： 12.0.0.0/24：这是 R1 的 F0/0 接口直连的网络。 24.0.0.0/24：这是 R1 从 R2 那里学习到的网络。但是，由于水平分割，R1 不会将这条从 R2 学来的路由再发送回给 R3，因为 R1 是通过 F0/0 接口从 R2 学到这条路由的，而它发送更新给 R3 使用的是 F0/1 接口。水平分割是“按接口”工作的，所以这个场景下是可以发送的。 更准确的分析：R1 通过 F0/0 从 R2 学到 24.0.0.0/24，跳数为2。当 R1 从 F0/1 接口发送更新给 R3 时，水平分割规则（从接口A学到的路由不从接口A发回）不阻止它从 F0/1 发出。因此，R1 会向 R3 通告 12.0.0.0/24 (直连，跳数1) 和 24.0.0.0/24 (从R2学到，跳数2)。   OSPF协议抓包分析 5.1 在全局配置模式下利用命令no router rip将R1，R2，R3和R4中的RIP协议清除掉；     R1#conf t （1）OSPF周期性发送Hello报文的目的IP地址是多少？ OSPF周期性发送Hello报文的目的IP地址是 224.0.0.5。  （2）OSPF交换路由的原则是：跟所有的路由器交换直连的路由信息，路由器使怎么实现的，如何在抓到的OSPF报文中分析这一点 OSPF通过洪泛（Flooding）机制与区域内所有路由器交换直连路由信息。 实现方式： 邻居发现：通过Hello报文建立邻居关系 数据库同步： 使用DB Description报文描述LSDB摘要 使用LS Request请求缺少的LSA 使用LS Update发送具体的路由信息 使用LS Ack进行确认 洪泛机制：每个路由器收到LSU后，会向其他邻居转发（除了来源邻居） 报文分析方法： 抓包观察完整的OSPF邻居建立过程 重点关注： DB Description报文中的LSA头部列表 LS Update报文中包含的具体路由信息（Network LSA） 观察同一个LSU如何在多个路由器间传播  （3）分析抓到的五种类型的OSPF报文 Type 1: Hello 报文 功能：建立和维护邻居关系 抓包特征： Type: 1 包含Router ID, Hello Interval, Dead Interval, Neighbor列表等 目的IP: 224.0.0.5 Type 2: Database Description (DBD) 功能：描述LSDB摘要，用于数据库同步 抓包特征： Type: 2 包含MTU，序列号，LSA头部列表 标志位：I（Init）、M（More）、MS（Master/Slave） Type 3: Link State Request (LSR) 功能：请求具体的LSA信息 抓包特征： Type: 3 包含请求的LSA类型、Link State ID、Advertising Router等 Type 4: Link State Update (LSU) 功能：发送具体的LSA信息 抓包特征： Type: 4 包含一个或多个完整的LSA 这是实际承载路由信息的报文 Type 5: Link State Acknowledgment (LSAck) 功能：确认收到LSU 抓包特征： Type: 5 包含被确认LSA的头部信息  （4）分析在Hello报文中选举DR和BDR的过程。 选举过程抓包分析： 初始状态： 所有路由器的DR/BDR字段都为0.0.0.0 互相发送Hello报文，交换优先级信息 选举阶段： 每个路由器比较收到的Hello报文中的优先级和Router ID 在下一个Hello周期中，开始填写DR/BDR字段 稳定状态： DR和BDR选举完成 所有路由器的Hello报文中DR/BDR字段一致 |
