一、实验目的及要求 实验19：掌握标准IP ACL的基本配置方法，实现基于源IP地址的访问控制，理解ACL在网络安全中的作用。  实验20：掌握扩展IP ACL的配置，实现基于源IP、目的IP、协议和端口的精细化访问控制。  实验21：掌握基于MAC地址的ACL配置方法，理解二层访问控制与三层ACL的区别。 |
| 二、实验原理与内容 实验19：标准IP ACL通过检查数据包的源IP地址，在路由器接口上进行流量过滤，实现简单的访问控制。本实验通过配置标准ACL，实现销售部门无法访问财务部门，行政部门可以访问的控制需求。  实验20：扩展IP ACL可检查IP包的五元组信息，适用于复杂访问控制场景。本实验实现宿舍网只能访问FTP服务器，教工网可访问FTP和WWW服务器。  实验21：基于MAC的ACL检查数据包的MAC地址，属于二层过滤，难以被用户绕过。本实验实现仅允许财务部主机访问财务服务器。 |

| 四、实验过程（实验步骤、记录、数据、分析） 实验19： 配置R1、R2基本接口IP地址。 配置静态路由确保网络连通。 在R2上配置标准ACL： access-list 1 deny 172.16.2.0 0.0.0.255   access-list 1 permit 172.16.1.0 0.0.0.255   将ACL应用到R2的F1/0接口出方向。 测试连通性。  实验20： 配置R1、R2接口与静态路由。 在R1上配置扩展ACL： access-list 100 permit tcp 172.16.1.0 0.0.0.255 host 172.16.4.2 eq ftp   access-list 100 permit tcp 172.16.2.0 0.0.0.255 host 172.16.4.2 eq ftp   access-list 100 permit tcp 172.16.2.0 0.0.0.255 host 172.16.4.3 eq www   将ACL应用到R1的S1/2接口出方向。 安装FTP与WWW服务器并测试。  实验21： 配置交换机VLAN与接口。 配置MAC ACL： mac access-list extended deny_to_acc   deny any host 000d.000d.000d   permit any any   将ACL应用到F0/2、F0/3接口入方向。 测试访问控制效果。 |
| 五、测试/调试及实验结果分析 实验19： 行政部（172.16.1.0/24）可ping通财务部主机。 销售部（172.16.2.0/24）无法ping通财务部主机。 结果符合预期，标准ACL部署成功。                                实验20： 宿舍网主机可访问FTP，无法访问WWW。 教工网主机均可访问FTP与WWW。 扩展ACL成功实现协议与端口级控制。                                                 实验21： 财务部主机可ping通财务服务器。 非财务部主机无法ping通财务服务器。 MAC ACL有效实现了基于物理地址的访问控制。 |
| 六、实验结论与体会 实验19： 通过本实验，理解了标准IP ACL的配置方法和应用场景，掌握了将其部署在靠近目标端的接口以优化网络流量的策略。  实验20： 扩展ACL功能强大，可灵活控制不同应用流量，适合部署在靠近源端的位置，减少不必要流量传输。  实验21： MAC ACL提供了一种更底层的安全控制方式，适用于同一网段内的访问控制，但配置时需注意交换机对入方向/出方向的支持情况。 |
