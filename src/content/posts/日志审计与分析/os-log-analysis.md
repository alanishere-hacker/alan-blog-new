| 二、实验原理与内容 一、实验原理 系统日志原理 日志是操作系统记录自身运行状态、用户操作、服务调用、安全事件的核心数据，相当于系统的 “行为黑匣子”。Linux 采用文本格式日志，Windows 采用专用的 EVTX 二进制格式日志，两者都能记录登录、进程、权限、网络等关键安全事件。 Windows 安全事件机制 Windows 系统会对每一次登录、登录失败、进程创建、权限调用等行为生成固定编号的事件 ID： 4624：登录成功 4625：登录失败 4688：进程创建 4673：特权 / 令牌操作 这些事件是日志审计、入侵检测、行为溯源的核心依据。 Python 日志解析原理 EVTX 是二进制格式，无法直接阅读，必须通过专用解析库（如 python-evtx）读取。Python 脚本通过加载日志文件，筛选关键字、统计事件数量、提取时间、用户、IP 等关键信息，实现自动化日志分析。 日志审计基本流程 获取日志 → 解析格式 → 筛选关键事件 → 统计与提取信息 → 分析行为特征 → 形成审计结论。 二、实验内容 Kali Linux 日志查看实践 在 Kali 系统中使用 journalctl 等命令查看系统日志，理解日志的结构、作用和基本内容，掌握系统日志的基础阅读方法。 Windows EVTX 日志样本获取 从公开安全日志项目下载多个 Windows 安全日志样本，包括登录事件、横向移动、权限操作等场景的 EVTX 文件。 Python 日志解析脚本编写与运行 编写 Python 解析脚本，解决环境依赖、库导入、文件路径等问题，实现对 EVTX 日志的读取与解析。 登录事件统计分析（脚本 1） 通过脚本统计日志中 4624（登录成功）、4625（登录失败）事件的总次数，输出统计结果并截图。 登录详情提取分析（脚本 2） 通过脚本从日志中提取登录时间、登录用户、来源 IP 等详细信息，展示关键审计字段并截图。 多日志样本对比分析 对不同场景的 EVTX 日志进行分析，观察不同事件 ID 的表现形式，理解各类系统行为在日志中的特征。 |

| 六、实验结论与体会 这次实验，让我从零开始接触了系统日志分析，虽然过程中遇到不少问题，但收获很真实。 在Kali Linux上，我学习使用journalctl查看系统日志。一开始面对大量杂乱的日志信息我会不知所措，只能简单浏览，后面的过程中我慢慢才体会到，日志就是系统的行为记录，每一条信息都对应着一次操作或状态变化。 再说说 Windows 日志和 Python 脚本。写脚本时我踩了不少坑：Windows 路径的反斜杠转义问题（后来查ai得知要在路径前加r）、Kali 里的库导入错误（ai不断教我才下载好所有东西），折腾了半天才跑通。 通过对比不同的evtx日志样本，我清楚了不同事件ID的含义，也能看出登录行为、远程操作、权限操作在日志中的不同特征。 这次实验让我明白，日志审计不在于工具多复杂，而在于读懂日志背后的系统行为。同时也让我明白，ai是我们的好老师，做实验中遇到的问题都可以请ai帮我们解决，并且还很高效。         2026年  4  月  28  日 |
